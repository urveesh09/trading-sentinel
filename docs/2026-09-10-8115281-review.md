# Review of 8115281 — September 10

Verdict: useful partial correction, not full closure of input and management readiness. Reviewed scanner/caller contracts, status persistence, setup UI and engine source. Production unchanged.

## Confirmed improvements

Valid no-direction scans no longer require an option chain. Missing profiles are explicit. Per-index latest status persists. Authenticated setup now exists in the dashboard. Qualification remains distinct; no research evidence or order authority was manufactured.

## Small corrections made in this review

- Non-finite and boolean bar prices cannot become management observations.
- Missing/stale/unusable observations and explicit insufficient-input signal reasons cannot be counted as healthy no-setup. They persist SIGNAL_INPUT_UNAVAILABLE instead.
- Background readiness polling no longer resets profile fields merely because input status changes. Form resets follow saved profile version/state changes.
- Save confirmation does not falsely assert qualification is blocked when it may already exist.

Validation: 64 selected Python tests passed (orchestrator, advisory and routes), including four new malformed-price regressions. Dashboard production build passed. This is not a claim that the full suite passed or a browser interaction test was performed.

## Remaining substantive work

1. Active management still awaits scan_underlying, which also fetches the option chain for a fired direction. Its error is handled before bar management. Thus a chain failure can still suppress a perfectly usable bar observation. Separate public-condition retrieval/management from entry-chain work; test active idea invalidation with chain failure and no new direction.
2. Conditional protection remains below directional-candidate early returns, so it is still coupled to a valid directional debit-spread setup. Move it into its own explicit-exposure branch. Do not infer holdings or turn it on implicitly.
3. Freshness_seconds is stored at write time and returned unchanged, while received_at defaults to the attempt clock. It is not current age or necessarily actual receipt time. Add injected fresh completion/receipt clock, current age calculated on reads, stale/future states, and monotonic update protection so older completions cannot overwrite newer evidence. Tests must advance time without a new scan.
4. Qualification state remains NOT_EVALUATED on quiet ticks even with registered qualifications; show current policy qualification independently from candidate generation, without implying any card is deliverable.
5. Source freshness and strategy/contract basis need explicit end-to-end management tests. Closed-bar condition checks are not tick-level protection and must be described truthfully to the manual trader.

The new setup UI solves the missing onboarding entry point. Operator still must save the explicit INTRADAY profile after deployment. Genuine reviewed intraday research remains outstanding and cannot be replaced by toggles. Do not call the partner-advisory product fully ready until input management and real qualification are demonstrated. Preserve these findings rather than suppressing the warnings.
