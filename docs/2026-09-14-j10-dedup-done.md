## The defensive contract

The J.10 gate answers: "have the CAS sub-window branches of
`classify_session_phase` been **exercised** by real captures?"

Before this slice, the gate's branch count was `len(captures[phase])`
where each file in `docs/j2_captures/` was a unit of evidence. An
operator who accidentally committed the same capture twice
(`cp RELIANCE_15_17.json RELIANCE_15_17.bak.json`, or a retry of
the probe without changing inputs) silently inflated the branch
count toward the REACHABLE threshold.

After this slice, the gate's branch count is **the number of
unique observations under that branch**. A fingerprint is
SHA-256[:16] of the capture bytes; the gate tracks every
fingerprint seen per branch and counts only the first occurrence
toward coverage. Duplicates surface in a new field
`duplicates_by_branch: dict[str, int]` so the operator can
prune them if they wish, but the gate's verdict is driven by
unique observations.

## Design decisions

- **Per-branch dedup, not global.** Two captures that legitimately
  exercise different branches (e.g. CAS_MATCHING and CAS_POST for
  the same trading day, different windows) keep their own count.
  The dedup is scoped to `fingerprints_by_branch[phase]`.
- **Bytes-path fingerprinting.** `fingerprint_of` reads the file
  bytes (not the parsed JSON object) and hashes with SHA-256.
  The J.3 probe writes a deterministic JSON document via
  `json.dumps(..., sort_keys=True)` (per the probe's canonicalisation
  discipline), so in practice the bytes-path and the parsed-dict-path
  converge. The bytes-path survives future probe changes.
- **64-bit collision probability is effectively zero.** The gate
  operates on a bounded number of captures (operator-curated
  staging evidence); 16 hex chars = 64 bits. Collision probability
  is ~1-in-2^32 per pair once you cross 4 billion captures -- the
  project will not see that volume in any one branch.
- **Catalog includes duplicate paths.** The per-branch
  `captures_by_branch` catalog surfaces ALL files contributing to
  the branch (including duplicates). Operators can see
  "RELIANCE_15_17.json appears twice" and investigate. The
  catalog is informational; the verdict is unaffected.
- **Unreadable files count as skipped.** If `fingerprint_of`
  returns `None` (the file vanished between the schema check and
  the hash), the gate treats it as `captures_skipped` rather
  than as a hash collision. Defensive against race conditions.
- **Backwards-compatible report shape.** The new field is
  ADDITIVE; all seven existing keys (`verdict`, `captured_phases`,
  `missing_phases`, `coverage_pct`, `captures_scanned`,
  `captures_skipped`, `captures_by_branch`) are byte-identical.
  The two existing tests that pinned the old shape are updated
  to pin the expanded shape.

## Senior-dev invariants preserved

- **NO deletions.** All previous behaviour is preserved; the new
  field is additive.
- **NO verdict-semantics change.** The verdict still answers
  "do all 6 branches have >= 1 capture?" -- the dedup makes
  that answer count **unique** observations, not files-on-disk.
  This is the senior-dev right move: the gate's *intent* was
  always unique observations; the dedup aligns the implementation
  with the intent.
- **NO F/G files touched.** Pure additive work on the J.10 surface.
- **NO new dependencies.** Stdlib only (`hashlib`, `pathlib`).
- **NO new tables, NO new SQL.** The dedup is computed in-memory
  during the existing `cas_reachability_report` walk.

## The 5 bounded invariants from the dedup contract

1. **Per-branch count = unique observations.** Two byte-identical
   captures under the same branch contribute `count=1`, not `count=2`.
2. **Catalog includes duplicates.** The per-branch
   `captures_by_branch` list shows every contributing file, even
   if it was a duplicate. Operators can prune the redundancy.
3. **`duplicates_by_branch` is always present.** Empty dict
   when no duplicates; populated counts when duplicates exist.
4. **Fingerprint length is 16 hex chars (64 bits).** Pinned in
   `FINGERPRINT_HEX_LENGTH`; exposed in the SUMMARY so operators
   can audit what "duplicate" means.
5. **`fingerprint_of(unreadable_path) -> None`.** The gate counts
   unreadable files as `captures_skipped`, not as duplicates.

## What this enables

The J.10 gate is now honest about what it counts. An operator
who sees `REACHABLE` knows it's REACHABLE because of unique
observations, not because of accidental file copies. The SUMMARY
surfaces the duplicates section so the operator can prune
redundancy if they want -- the verdict is unaffected, but the
audit trail is complete.

## What this slice deliberately does NOT include

- **No freshness / age filtering.** Captures older than N days
  still count toward coverage. A future slice (`J.10.FRESHNESS`)
  will add `--captures-since <DAYS>` so the operator can
  answer "is the gate REACHABLE with captures from the last
  7 days?" without manual inspection.
- **No minimum-captures-per-branch threshold.** The current
  contract is `>=1 capture per branch`; a future slice could
  raise this to `>=2` if the operator wants defence against
  a single flaky capture flipping the gate. Out of scope here.
- **No F/G cross-workstream.** The dedup is pure J.10 surface.
